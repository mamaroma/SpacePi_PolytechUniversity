# SDR в основном сервисе

Основной сервис подключает SDR через `app/sdr_bridge.py`. Страница открывается по
`/sdr`, API — по `/sdr/api`, а браузер получает FFT-кадры через
`/sdr/ws/sdr`. При отсутствии IQ со станции сервис показывает
фоновый спектр. Пользовательский статус при этом — «Ожидание пролёта»;
«Пролёт» показывается при поступлении настоящих IQ-кадров.

## Приём IQ со станции

Станция подключается к `/sdr/ws/iq-ingest` и отправляет бинарные кадры
`complex64` (пары `float32 I, Q`, порядок байтов платформы GNU Radio).
Нынешний `tracking_station/iq_relay.py` отправляет именно такие кадры и
остаётся совместимым. Размер каждого кадра должен быть кратен 8 байтам и
не превышать `IQ_MAX_FRAME_BYTES` (по умолчанию 2 МиБ). Одновременно
допускается один источник IQ.

Перед первым кадром станция **может** отправить текстовое WebSocket-сообщение:

```json
{
  "type": "station_hello",
  "station_id": "Polytech ground station",
  "sample_rate": 625000,
  "center_frequency": 436610000,
  "satellite_name": "Polytech Universe"
}
```

Сервис ответит `station_ack`. Без этого сообщения IQ тоже принимается,
а спектр использует настройки из расписания или значения по умолчанию.
Фактический статус доступен по `GET /sdr/api/stream/status`.
`station_connected` означает открытый WebSocket, `streaming` — кадры
поступали за последние 2,5 секунды. Счётчики сбрасываются при новом
подключении станции.

Для развёртывания с доступом извне задайте одинаковый
`SDR_INGEST_TOKEN` на сервисе и станции. Станция передаёт его в заголовке
`X-SDR-Token` либо как параметр `?token=...` при установлении WebSocket.
Пока переменная не задана, старый relay без токена работает; сервер
выводит предупреждение. Изменение relay и его настроек относится к
отдельному шагу работы со станцией.

Локальный ZMQ-приёмник основного сервиса по умолчанию выключен. Его можно
включить через `SDR_ENABLE_ZMQ=1` для старой схемы с локальным GNU Radio.
Настройки `ZMQ_ADDRESS`, `DEFAULT_SAMPLE_RATE` и
`DEFAULT_CENTER_FREQUENCY` остаются доступными.

## Записи и расписание

Пользовательскую запись можно запустить в любое время, в том числе при
отсутствии пролёта. После остановки браузер автоматически скачивает IQ-файл.
Для длинных записей сервис временно записывает поток в системный каталог
временных файлов; после передачи файл удаляется. Незагруженный файл удаляется
через 10 минут, незавершённая запись — через час. При штатной остановке
сервиса временные файлы тоже удаляются. Пользовательские записи не попадают
в серверный архив. Размер одного файла ограничен `MAX_RECORDING_SIZE_GB`
(по умолчанию 10 ГБ).

Настоящий IQ-поток со станции записывается отдельно и автоматически в
`sdr/sdr_web_test/data/recordings` как `*_auto.iq`. Запись завершается через
5 секунд после прекращения потока. Она остаётся на сервере 48 часов после
завершения пролёта и удаляется вместе с метаданными при ближайшей ежеминутной
очистке. Фоновый шум в эти файлы не попадает. Интерфейс SDR не показывает
архив и не воспроизводит записи.

API: `POST /sdr/api/record/start` возвращает `recording_id`; этот секретный
идентификатор нужен для `POST /sdr/api/record/stop`,
`GET /sdr/api/record/state/{recording_id}` и однократного скачивания через
`GET /sdr/api/record/download/{recording_id}`. Остановленная запись также
возвращает `download_url`. Отменить запись можно через
`POST /sdr/api/record/cancel`.

`POST /sdr/api/passes` обновляет расписание и сохраняет его в
`sdr/sdr_web_test/data/passes.json`, чтобы оно переживало перезапуск
сервиса. Время в API — UTC, в интерфейсе — московское.

## Локальный просмотр

В Windows PowerShell из корня проекта откройте два терминала. В первом
выполните `./scripts/dev-api.ps1`, во втором — `./scripts/dev-ui.ps1`.
Остановить их можно `Ctrl+C` в каждом терминале. Основной сервис доступен на
`http://127.0.0.1:5173/`, SDR — на `http://127.0.0.1:5173/sdr`.
Сам SDR также открывается напрямую на `http://127.0.0.1:8000/sdr`.
Фоновый шум позволяет проверить страницу без SDR-приёмника.
